# `plan/` — working material, **not finalized**

Everything in this directory is provisional. It records options under
consideration, not commitments.

**Students:** nothing here is part of the syllabus, and nothing here should be
treated as an obligation, a promise, or a study guide. If a topic, project, or
assessment appears in this directory and nowhere else, it has **not** been
assigned and may never be. Only material that has been officially announced —
through the syllabus, the class Discord, or a distributed assignment — counts.

Where this directory and an official course document disagree, **the official
document is correct**.

## What lives here

| File | What it holds |
|---|---|
| `MATH231_projects_and_demos.tex` / `.pdf` | The full menu of candidate projects and lecture demos, plus a draft assessment mapping. Which projects are actually assigned is still being decided. |
| `MATH231_tentative_topics.tex` / `.pdf` | Topics appearing across the course progression that are **not guaranteed** to be covered, gathered in one place. |

## Why it is separate

The course progression document (`course_plan/`) describes the material the
course is built around. It was carrying two kinds of content that do not belong
next to each other: what the course *will* cover, and what it *might*. Splitting
them keeps the progression honest — anything still undecided lives here, so the
progression can be read as a statement of intent rather than a wish list.

The project menu in particular is deliberately larger than what will be
assigned. Three projects are graded this semester; the menu lists nine
candidates. Selecting from it is still in progress.

> **Note on the draft assessment mapping.** It predates the finalized grading
> split and does not match it — it shows four projects and ten homework
> assignments, where the course actually has **three projects and five homework
> assignments** (see the root `README.md` for the authoritative weights). The
> mapping is kept for its unit-coverage sketch, not its counts.
